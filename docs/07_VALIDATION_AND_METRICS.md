# S.T.A. Validation & Metrics

## 1. 현재 Stage

FACT:
- 유료 S.T.A. Pilot 없음
- 아이디어 논의 경험 있음
- 4050 AI Cafe Prototype 있음
- S.T.A. Web Prototype v0.1 있음

따라서 현재 Stage:
Problem Discovery / Pre-validation

## 2. 검증해야 할 순서

1. Problem
2. Customer
3. Learning Experience
4. Willingness to Pay
5. Learning Outcome
6. 30-Day Use
7. Cohort Economics
8. B2B Repeatability
9. Software Leverage

플랫폼 확장은 이 순서를 건너뛰지 않는다.

## 3. Initial Targets

아래는 FACT가 아니라 TARGET:
- 고객 인터뷰 30명
- Workflow Diagnosis 20건
- 유료 초기고객 10명
- 첫 Cohort 6~8명
- Seed Sandbox Case 6개 완성
- 50~100개 Problem Case 축적은 중기 목표

## 4. Interview Questions

피해야 할 질문:
“이 서비스 좋으세요?”
“수강하시겠어요?”

권장:
- 최근 한 달 동안 반복한 PC 업무는?
- 가장 싫은 반복업무는?
- 몇 분/시간 걸리는가?
- 누구에게 넘기거나 자동화하려 해본 적이 있는가?
- AI로 시도했다면 어디서 막혔는가?
- 결과를 직접 수정해야 하는가?
- 회사 데이터를 외부 AI에 넣을 수 있는가?
- 2일/20시간/40시간 중 현실적으로 가능한 방식은?
- 돈을 낸다면 어떤 결과가 있어야 하는가?

## 6. Learning Outcome Metrics

완주율만으로 평가하지 않는다.

핵심:
- Design: 새 문제를 구조화
- Detect: Failure 발견
- Fix: 수정
- Modify: Business Rule 변화 반영
- Transfer: 새로운 Case에 적용

Pilot 평가도구 예:
Unseen Case를 주고 다음 요소를 평가:
- Problem
- Input
- Process
- Rule
- AI Role
- Human Role
- Exception
- Approval
- Output

## 7. Usage Metrics

실제 업무 적용 Cohort에서:
- Workflow 실제 사용 여부
- 30-Day Active Workflow
- Self-edit 성공 여부
- Workflow Reuse
- 새 업무로 Transfer
- Referral
- Repeat Learning Intent

시간절감은 보조지표. 실제 측정 없이 Marketing Claim으로 사용하지 않는다.

## 9. 20h vs 40h vs 2-Day Experiment

HYPOTHESIS:
- 2-Day: 집중체험/B2B 진입
- 20h: 재직자에게 현실적
- 40h: Architect 역량전이에 더 적합

검증:
- 모집률
- Attendance
- Completion
- Canvas Quality
- Transfer Test
- WTP
- Referral
- 30-Day Use

단순 만족도만으로 상품 Winner를 정하지 않는다.

## 10. Seed Case Validation

각 Case마다:
- Mission 이해율
- Canvas 시작률
- Hint 사용률
- Failure 완수율
- Reference Architecture 열람시점
- Modification 성공
- “내 업무와 유사함” 정도

질문:
어떤 Case가 고객을 가장 잘 끌어들이는가?
어떤 Case가 학습효과를 가장 잘 만드는가?
둘은 다를 수 있다.

## 11. Core PMF Signals

초기 교육서비스에서 보고 싶은 신호:
- 자발적 유료전환
- 다른 업무를 가져옴
- 본인이 Workflow를 수정
- 동료를 추천
- 기업에서 다음 Cohort 요청
- 학습자 실제업무가 새로운 Case로 재탄생

특히:
“첫 번째 과정에서 7번째 Case가 학습자의 실제 업무에서 탄생하는가?”

## 12. Evidence Rule

모든 발표/문서/웹 카피에서:
- FACT에는 출처 또는 실제 데이터
- HYPOTHESIS에는 가설 표시
- TARGET에는 목표 표시

실제 Pilot 후에도 표본크기, 측정기간, 대상 고객을 같이 기록한다.
