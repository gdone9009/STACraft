# 랜딩페이지 V2 개선 검토

## 근거
이전 대화 검색에서 S.T.A. 브랜드, 경력자의 전략적 설계 역량, 클릭 가능한 프로토타입, 문서 갱신 요청을 확인했다. 대화 전체 원문을 확보한 것은 아니며, 실제 구현과 최신 기준은 저장소 AGENTS.md, 사업계획 v5, PRD, 인수인계 문서를 기준으로 삼았다.

| 기존 문제 | 개선 |
|---|---|
| 영어 개념과 추상적 가치 제안이 많음 | 익숙한 보고·회의·문의 업무와 한국어 역할 설명 |
| 첫 버튼 이후 다시 과제를 고르게 됨 | 데이터가 있는 영업보고 과제로 바로 진입 |
| 과제 선택 시 문제를 읽기 전에 설계 화면 진입 | 문제 이해를 첫 단계로 수정 |
| 과정별 카드만 있어 차이 비교가 어려움 | 시간·대상·학습 목표 선택기 |
| 6개 학습팩이 모두 완성된 것처럼 읽힘 | 데이터 예제 1개 / 상세 데이터 준비 중 5개 표시 |
| 과제는 8명인데 데이터는 3명 | 가상 직원 3명으로 일치 |
| 모든 과제의 변경 질문이 영업 80→85% | 영업 외 과제는 누락 자료 확인 질문 |
| 저장·모집·체험 범위 안내 부족 | FAQ와 명시적 준비 상태 |
| 작은 입력 글자 및 버전 비교 부재 | 16px 입력·키보드 포커스·V1/V2 전환 |

## 한계와 다음 작업
전환율 개선은 아직 측정하지 않았으며, 효과가 입증됐다는 주장은 하지 않는다. 모집 일정과 신청 수신처 확정 후 실제 신청 동선을 연결한다. Case Pack 확장과 저장·내보내기는 후속 교육 MVP 작업이다.

## 검증 결과
- `npm run build`: 통과.
- `git diff --check`: 통과.
- V1 소스는 원본에서 진입점·컴포넌트 이름만 분리하여 보존.
- 브라우저 자동 검증은 실행 환경에 Chromium이 없고 설치 다운로드가 시간 초과되어 미완료. 모바일 실제 렌더링, 버튼 클릭, 콘솔 오류 여부를 브라우저에서 확인했다고 주장하지 않는다.
